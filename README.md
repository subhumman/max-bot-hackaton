# MAX Equipment Bot

Чат-бот учёта сроков службы инженерного оборудования в МКД на платформе MAX.
(a95d9494475e5b51eaedea549a8bbec64a99fa6f - commit hash)
**Бот в MAX:** https://max.ru/t315_hakaton_max_bot

---

## 1. Назначение решения

Решение предназначено для управляющих компаний и собственников жилья, которые ведут учёт технического оборудования дома (счётчики, насосы, бойлеры, автоматы и др.).

**Задачи:**
- единый реестр оборудования с датами установки и нормативными сроками службы;
- контроль остаточного ресурса и статусов (в норме / скоро менять / просрочено);
- упреждающие напоминания о плановой замене (90 / 30 / 7 дней);
- подбор совместимых аналогов;
- сводка по фонду для диспетчера УК.

Цель — перевести замену оборудования из аварийного режима в плановый.

---

## 2. Основной пользовательский сценарий

1. Пользователь открывает бота в MAX и нажимает «Начать» / отправляет `/start`.
2. Выбирает **город** → **управляющую компанию** → **дом (ЖК)**.
3. Указывает роль:
   - **Собственник** — доступ к своему дому;
   - **Диспетчер УК** — доступ после ввода пароля, плюс сводка по всем домам УК.
4. В главном меню:
   - просматривает список устройств по категориям;
   - открывает карточку прибора (срок, остаток дней, статус 🟢🟡🔴);
   - подписывается на напоминания (90 / 30 / 7 дней);
   - при необходимости смотрит аналоги.
5. Диспетчер УК открывает «Сводка по УК» и видит количество просроченных и критичных приборов.
6. В день наступления порога (90 / 30 / 7 дней) бот автоматически присылает напоминание.

## 4. Запуск через Docker

Одна команда для поднятия всех локальных компонентов:

```bash
docker compose up --build
docker compose down # остановка 
Remove-Item -Force data\equipment.db -ErrorAction SilentlyContinue # удаление старой базы
(или же так) rm -f data/equipment.db
```

9. Работа с данными
Хранилище: SQLite (data/equipment.db).
Основные сущности:

uk — управляющие компании
buildings — дома (ЖК), привязка к городу и УК
devices — оборудование (тип, модель, даты, статус)
users — пользователи MAX, роль, выбранный дом
subscriptions — подписки на напоминания
analogs — совместимые аналоги по типу прибора

Статусы устройств (пересчитываются ежедневно):

ok — до замены > 90 дней
soon — до замены ≤ 90 дней
overdue — срок вышел

Источники данных на проде (задел):

Выгрузка из 1С УК / «Паспорт дома»
Оцифровка актов ввода в эксплуатацию
API производителей (телеметрия)
Ручной ввод через бота

На демо используются сиды на основе нормативов (ВСН 58-88(р), паспорта изделий, ГОСТы).

10. Порядок работы с тестовыми данными
При старте контейнера автоматически выполняется 
```bash 
python seed.py
``` 
затем 
```bash
python main.py.
```
Скрипт seed:

пересоздаёт таблицы;
создаёт 4 УК, 3 города, 7 домов;
генерирует устройства (часть со статусами soon/overdue);
заполняет справочник аналогов.

Повторный запуск seed безопасен — данные пересоздаются.
Вручную внутри контейнера:
```bash
docker compose exec bot python seed.py
```

13. Известные ограничения

Long polling — для демо; на production предпочтителен webhook + HTTPS.
Нет нативных dropdown в MAX — навигация через inline-кнопки.
Сиды синтетические; выгрузок из 1С в MVP нет.
Один общий пароль диспетчера УК (на проде — код на УК или SSO).
Аналоги — ограниченный справочник-заглушка.
При смене схемы БД нужна пересборка volume (rm data/equipment.db).


14. Остановка и повторный запуск
Остановка:
```Bash
docker compose down
# или Ctrl+C при локальном запуске python main.py
```

Повторный запуск:

```Bash
docker compose up --build
# данные в volume сохраняются; для сброса сидов:
docker compose run --rm bot python seed.py
```

Сброс БД:

```Bash
docker compose down
rm -f data/equipment.db
docker compose up --build
```

15. Внешний сервис, необходимый для MVP
MAX Bot API (https://platform-api2.max.ru)

Назначение: доставка сообщений, приём нажатий кнопок, long polling / webhook.
Почему нельзя воспроизвести в Docker: это облачный API мессенджера MAX.
Условия проверки решения:
Валидный токен бота.
Бот опубликован и доступен по ссылке.
Среда запуска имеет исходящий HTTPS-доступ к API MAX.
